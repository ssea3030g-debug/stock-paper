# 독서 모의시험지 제작 — 작업 방법 총정리 (다른 세션용)

브랜치: `claude/merge-exam-original-text-crciew`, 작업 폴더 `exam_merge/`. 세부 이력은 `HANDOFF.md`, 기출 분석은 `출제규칙_초안.md`.
사용자는 보인고 2학년 독서(비문학) 중간고사를 준비한다. 시험 범위는 `variant_변형본.pdf`의 29개 지문(인문 8·사회 9·과학 5·기술 5·예술 2). **니체(인문08)와 페로브스카이트(기술04)는 사용자가 "고려 대상에서 제외"하라고 했다.**

## 1. 환경과 준비
- 필요한 도구: poppler(pdftotext, pdftoppm), ImageMagick(convert, montage), node + playwright(chromium), python3. `pip`/`npm`/CDN은 프록시에 막혀 있어 새 패키지는 못 받는다(fonttools 없음).
- 글꼴은 `fonts/`에 있다. 변형본에서 꺼낸 나눔명조 부분 글꼴(`U_*.ttf`) + 전체 글꼴 `NanumMyeongjo-Regular/Bold.ttf`, `NanumGothic-Bold.ttf`(google/fonts를 `git clone --depth 1 --filter=blob:none --sparse https://github.com/google/fonts.git` 후 `sparse-checkout`으로 받음, github.com은 열려 있다). 나눔명조에도 없는 ⓐ~ⓔ, Ⅰ~Ⅲ, ㎐, ㎛, 한자는 WenQuanYi로 찍힌다.
- 이미지 확인: `pdftoppm -r 60 -png`로 뽑아 `montage`로 여러 쪽을 한 장으로 합쳐 Read로 본다(그림 요청 한도 때문에 한 번에 여러 쪽을 보는 게 효율적).
- 임시 작업물은 scratchpad에 두고, 쓸 만한 도구는 반드시 `exam_merge/tools/`로 옮겨 커밋한다(세션이 끝나면 /tmp는 사라진다).

## 2. 파이프라인 한눈에
```
originals/*.pdf (학력평가 고2 11회분)  ──build.cut_passage──▶ 지문 이미지(원문 상자를 잘라 이음매 없이 이어 붙임)
문항 JSON (custom_questions/…, mock_*/sets/…) ──render_custom.html_of──▶ 문항 PNG(300dpi, playwright 스크린샷)
                             지문+문항 ──build.py / build_combo.py / build_exam.py──▶ A4 PDF(playwright pdf)
```
| 스크립트 | 역할 | 명령 |
|---|---|---|
| `build.py` | 변형본 PDF에 원문 지문을 끼워 넣은 합본(지문별 한 세트) | `python3 exam_merge/build.py --variant exam_merge/variant_변형본.pdf --orig-dir exam_merge/originals --out 결과.pdf [--only 기술02,인문01]` (전체 약 5분) |
| `render_custom.py` | `custom_questions/**/*.json` → 같은 이름 `.png` | `python3 exam_merge/render_custom.py` |
| `build_combo.py` | 지문 3개를 (가)(나)(다)로 묶은 세트(`combo_sets.json`) | `python3 exam_merge/build_combo.py --out 고난도_가나다_3세트.pdf` |
| `build_exam.py` | **기출 모양의 시험지**(머리글·실시일 표·2단·발문 "[1~3, 단답형1] 다음 글을 읽고…"·정답표) | `python3 exam_merge/build_exam.py --exam exam_merge/mock_h1/exam.json --out 모의고사1회_고난도.pdf --work <작업폴더>` (약 1~2분) |
| `tools/qtool.py` | `write <세트> <spec.json>`: 문항 JSON 쓰기+글꼴 누락 검사 / `check`: 검사만 | |
| `tools/lencheck.py` | `python3 exam_merge/tools/lencheck.py mock_h1`: 정답이 가장 긴 선지인 비율, 정답 번호 분포 | |
| `tools/extract_passages.py` | 29개 지문 원문 텍스트를 뽑아 `$OUT/<지문>.txt`로 저장(`OUT=/tmp/pt`) → **문항 쓰기 전에 반드시 읽는다** | `OUT=/tmp/pt python3 exam_merge/tools/extract_passages.py` |

지문 ID는 `인문01`…`예술02`(변형본 제목 앞 두 단어). 지문 원본 위치는 변형본 각 쪽의 출처 줄("2025년 3월 고2 27-30번")로 찾는다.

## 3. 시험지 한 벌 만드는 순서(`build_exam.py` 기준)
1. 지문 원문을 읽는다(`extract_passages.py`). 문항은 **지문 안의 내용만으로** 풀려야 한다(지문에 없는 단위·공식·계산 금지, 지문에 있는 수치·규칙을 쓴 사례는 허용).
2. 세트별 JSON을 `mock_xxx/sets/NN_지문.json`에 쓴다(아래 §4). 세트 하나 = 지문 하나(또는 `combo`).
3. `mock_xxx/exam.json`에 제목·날짜·`footer`·`scores`(선택형 배점 32개, 합 94)·`sets`(파일과 `parts`)를 적는다. 단답형은 stem에 `[단답형n]`과 배점을 직접 쓴다(선택형 94 + 단답형 6 = 100점). `parts`가 2~3개면 (가)(나)(다) 세트.
4. `build_exam.py` 실행 → PDF 확인(`pdftoppm`+`montage`) → `lencheck.py`로 정답 길이 점검 → 수정 후 재빌드.
5. 커밋·푸시 → 사용자에게 `SendUserFile`로 PDF 전달(마지막 쪽이 정답표).

## 4. 문항 JSON 형식
```json
{"stem": "발문(번호·배점 없이)", "pos": 3,          // pos: 정답 선지를 choices 맨 앞에 쓰고 정답 번호 자리를 지정
 "bogi_text": "<보기> 본문(\n 줄바꿈 허용)",        // 선택
 "bogi_lines": ["ㄱ. …", "ㄴ. …"],                   // 선택(ㄱㄴㄷㄹ형. 이때는 pos 대신 "answer": "④" 직접)
 "table": [["머리","…"],["행","…"]],                 // 선택(<보기> 속 표)
 "choices": ["…", "…", "…", "…", "…"],               // 5개. ㄱㄴ 조합형은 짧게 → 자동으로 3열 배치
 "short": true, "answer": "㉮ …, ㉯ …"}             // 단답형
```
- 발문의 "않은 것/틀린 것/없는 것/다른 하나"는 렌더러가 자동 밑줄. 정답 번호는 ①~⑤에 고르게 분포시킨다.
- 표 머리글은 짧게(긴 머리글은 줄바꿈되지만 열이 많으면 폭이 넘친다 — 1회 31번 사례).
- 그림·그래프 `<보기>`는 **미지원**(표만 가능). 필요하면 SVG/PNG 생성 기능을 `render_custom.py`에 추가해야 한다.

## 5. 출제 원칙(사용자 피드백으로 굳어진 것)
- 기출 분석(보인고 2025-2 중간·기말): 지문 세트당 2~5문항, 발문은 "윗글을 바탕으로 <보기>를 이해한 내용으로 가장 적절한/적절하지 않은 것은?", 배점 [2.6~3.6점], 단답형은 기말에 세트 1·4·7번째에.
- **난이도 — 사용자가 "너무 쉽다"고 지적한 뒤 정리한 원칙**
  1. 선지 길이를 5개 모두 비슷하게. 처음엔 정답이 항상 가장 길어서(71%) 지문을 안 읽고도 맞혔다. 목표: 정답이 최장인 비율 약 20%, 길이 순위도 한쪽으로 몰리지 않게(`lencheck.py`).
  2. 오답은 **앞은 지문과 맞고 뒤(원인·조건·주체·시점) 하나만 틀리게**. 처음부터 말이 안 되는 오답 금지.
  3. 선지 하나에 정보 2~3개, 서로 다른 단락에 걸쳐 엮기. 인과 방향 뒤집기, 두 학자의 근거 바꿔 끼우기, 정의 맞바꾸기, 범위 과장("마저/언제나/전혀").
  4. 사례 `<보기>`는 규칙 3개 이상·사람 3명·날짜 3개 이상, 수치는 2단계 이상(법정 기한 2년·5년, 법 개정 전후, 분포 용적, 친자 판별 표 등).
  5. 워딩은 지문 표현을 그대로 쓰지 않고 바꿔 말한다(사용자가 "훨씬 더 애매하고 어렵게"라고 요청).
  6. 단답형은 빈칸 옮겨 쓰기가 아니라 **사례 판별**(옳은 학생 이름 모두, 확정 방식 분류, 진리 유형 분류).
- 이미 낸 문항과 겹치지 않게 새로 낸다(변형본, 고난도 가나다, 모의 1·2회, 미니, 미니 고난도, 1·2회 고난도 재출제판).

## 7. 학생 답안 채점(스캔 PDF)
- `pdftoppm -r 80`으로 쪽을 보고, 문항별로 `-r 150`~`400` 크롭(`convert … -crop`)해 손글씨 체크·취소선·단답 글씨를 읽는다. 체크가 번호 사이에 걸치면 어느 쪽으로 읽었는지 밝힌다.
- 채점표(번호·학생 답·정답·배점)와 틀린 문항 해설, 약점 분석을 준다. 채점 중 출제 오류를 발견하면 즉시 고쳐 알린다(미니 7번 선지가 확정 불가였던 사례).

## 8. 지금 보류 중인 요청
