# 독서 모의시험지 제작 — 작업 방법 총정리 (다른 세션용)

브랜치: `claude/merge-exam-original-text-crciew`, 작업 폴더 `exam_merge/`. 세부 이력은 `HANDOFF.md`, 기출 분석은 `출제규칙_초안.md`.
사용자는 보인고 2학년 독서(비문학) 중간고사를 준비한다. 시험 범위는 `variant_변형본.pdf`의 29개 지문(인문 8·사회 9·과학 5·기술 5·예술 2). **니체(인문08)와 페로브스카이트(기술04)는 사용자가 "고려 대상에서 제외"하라고 했다.**

## 1. 환경과 준비
- 필요한 도구: poppler(pdftotext, pdftoppm), ImageMagick(convert, montage), node + playwright(chromium), python3. `pip`/`npm`/CDN은 프록시에 막혀 있어 새 패키지는 못 받는다(fonttools 없음).
- 글꼴은 `fonts/`에 있다. 변형본에서 꺼낸 나눔명조 부분 글꼴(`U_*.ttf`) + 전체 글꼴 `NanumMyeongjo-Regular/Bold.ttf`, `NanumGothic-Bold.ttf`(google/fonts를 `git clone --depth 1 --filter=blob:none --sparse https://github.com/google/fonts.git` 후 `sparse-checkout`으로 받음, github.com은 열려 있다). 나눔명조에도 없는 ⓐ~ⓔ, Ⅰ~Ⅲ, ㎐, ㎛, 한자는 WenQuanYi로 찍힌다.
- 이미지 확인: `pdftoppm -r 60 -png`로 뽑아 `montage`로 여러 쪽을 한 장으로 합쳐 Read로 본다(그림 요청 한도 때문에 한 번에 여러 쪽을 보는 게 효율적).
- 임시 작업물은 scratchpad에 두고, 쓸 만한 도구는 반드시 `exam_merge/tools/`로 옮겨 커밋한다(세션이 끝나면 /tmp는 사라진다).

## 2. 파이프라인 한눈에
```
originals/*.pdf (학력평가 고2 11회분)  ──build.cut_passage──▶ 지문 이미지(원문 상자를 잘라 이음매 없이 이어 붙임)
문항 JSON (custom_questions/…, mock_*/sets/…) ──render_custom.html_of──▶ 문항 PNG(300dpi, playwright 스크린샷)
                             지문+문항 ──build.py / build_combo.py / build_exam.py──▶ A4 PDF(playwright pdf)
```
| 스크립트 | 역할 | 명령 |
|---|---|---|
| `build.py` | 변형본 PDF에 원문 지문을 끼워 넣은 합본(지문별 한 세트) | `python3 exam_merge/build.py --variant exam_merge/variant_변형본.pdf --orig-dir exam_merge/originals --out 결과.pdf [--only 기술02,인문01]` (전체 약 5분) |
| `render_custom.py` | `custom_questions/**/*.json` → 같은 이름 `.png` | `python3 exam_merge/render_custom.py` |
| `build_combo.py` | 지문 3개를 (가)(나)(다)로 묶은 세트(`combo_sets.json`) | `python3 exam_merge/build_combo.py --out 고난도_가나다_3세트.pdf` |
| `build_exam.py` | **기출 모양의 시험지**(머리글·실시일 표·2단·발문 "[1~3, 단답형1] 다음 글을 읽고…"·정답표) | `python3 exam_merge/build_exam.py --exam exam_merge/mock_h1/exam.json --out 모의고사1회_고난도.pdf --work <작업폴더>` (약 1~2분) |
| `tools/qtool.py` | `write <세트> <spec.json>`: 문항 JSON 쓰기+글꼴 누락 검사 / `check`: 검사만 | |
| `tools/lencheck.py` | `python3 exam_merge/tools/lencheck.py mock_h1`: 정답이 가장 긴 선지인 비율, 정답 번호 분포 | |
| `tools/extract_passages.py` | 29개 지문 원문 텍스트를 뽑아 `$OUT/<지문>.txt`로 저장(`OUT=/tmp/pt`) → **문항 쓰기 전에 반드시 읽는다** | `OUT=/tmp/pt python3 exam_merge/tools/extract_passages.py` |

지문 ID는 `인문01`…`예술02`(변형본 제목 앞 두 단어). 지문 원본 위치는 변형본 각 쪽의 출처 줄("2025년 3월 고2 27-30번")로 찾는다.

## 3. 시험지 한 벌 만드는 순서(`build_exam.py` 기준)
1. 지문 원문을 읽는다(`extract_passages.py`). 문항은 **지문 안의 내용만으로** 풀려야 한다(지문에 없는 단위·공식·계산 금지, 지문에 있는 수치·규칙을 쓴 사례는 허용).
2. 세트별 JSON을 `mock_xxx/sets/NN_지문.json`에 쓴다(아래 §4). 세트 하나 = 지문 하나(또는 `combo`).
3. `mock_xxx/exam.json`에 제목·날짜·`footer`·`scores`(선택형 배점 32개, 합 94)·`sets`(파일과 `parts`)를 적는다. 단답형은 stem에 `[단답형n]`과 배점을 직접 쓴다(선택형 94 + 단답형 6 = 100점). `parts`가 2~3개면 (가)(나)(다) 세트.
4. `build_exam.py` 실행 → PDF 확인(`pdftoppm`+`montage`) → `lencheck.py`로 정답 길이 점검 → 수정 후 재빌드.
5. 커밋·푸시 → 사용자에게 `SendUserFile`로 PDF 전달(마지막 쪽이 정답표).

## 4. 문항 JSON 형식
```json
{"stem": "발문(번호·배점 없이)", "pos": 3,          // pos: 정답 선지를 choices 맨 앞에 쓰고 정답 번호 자리를 지정
 "bogi_text": "<보기> 본문(\n 줄바꿈 허용)",        // 선택
 "bogi_lines": ["ㄱ. …", "ㄴ. …"],                   // 선택(ㄱㄴㄷㄹ형. 이때는 pos 대신 "answer": "④" 직접)
 "table": [["머리","…"],["행","…"]],                 // 선택(<보기> 속 표)
 "choices": ["…", "…", "…", "…", "…"],               // 5개. ㄱㄴ 조합형은 짧게 → 자동으로 3열 배치
 "short": true, "answer": "㉮ …, ㉯ …"}             // 단답형
```
- 발문의 "않은 것/틀린 것/없는 것/다른 하나"는 렌더러가 자동 밑줄. 정답 번호는 ①~⑤에 고르게 분포시킨다.
- 표 머리글은 짧게(긴 머리글은 줄바꿈되지만 열이 많으면 폭이 넘친다 — 1회 31번 사례).
- 그림·그래프 `<보기>`는 **미지원**(표만 가능). 필요하면 SVG/PNG 생성 기능을 `render_custom.py`에 추가해야 한다.

## 5. 출제 원칙 (상세)

### 5-1. 기출 분석에서 나온 틀 (보인고 2025-2 중간·기말 독서, 같은 출제자로 판단)
- 시험 구성: 선택형 32 + 단답형 3(기말), 지문 세트 9~10개, 세트당 2~5문항(과학 복합 지문은 5~8). 지문은 단일, 또는 (가)(나)(다) 복수. 배점은 발문 끝 `[2.6~3.6점]`(어려울수록 높음, <보기> 적용·계산형이 3.4~3.6).
- 유형 비율: <보기> 적용 약 30~40%, 내용 일치·추론 약 35%, 서술 방식 세트당 1, ㉠㉡ 비교·이유, 문맥 어휘(ⓐ~ⓔ), 그림·표, 관점 비교·비판. "적절하지 않은 것은?" 35~40%(부정어는 밑줄).
- 영역 비율: 인문·사회 위주, 과학·기술은 큰 복합 지문 1개씩, 예술 1세트. 시험 범위 안에서 영역 수를 이 비율에 맞춘다.
- 선지 문체: "~겠군", "~볼 수 있다", "~하므로 ~이다"처럼 근거를 붙인 1~3줄 문장. 오답에도 정답과 같은 분량의 근거가 붙는다.

### 5-2. 절대 규칙 (어기면 사용자가 바로 지적했다)
1. **지문 안의 내용만으로 풀리게.** 지문에 없는 단위·공식·배경지식으로 계산하게 하지 않는다(kWh 계산 문항으로 지적받음). 지문에 나온 수치·관계식(예: COPH = COPC+1, 생체이용률×투여량, 분포 용적 = 혈액 도달량 ÷ 혈장 농도, ±5% 기준, 2년·5년 기한)을 새 사례에 적용하는 것은 허용.
2. **원본 학력평가 문항·학원 문항을 베끼지 않는다.** 참고만 한다. 외부 학원 시험지(저작권 표기·배포 제한이 있는 것)는 문항을 그대로 옮기지 않는다.
3. **<보기> 사례는 확정 가능해야 한다.** 주어진 조건만으로 정답이 하나로 정해지는지 직접 풀어 확인한다. (실패 사례: 부모 결괏값 '3-7'·'5-6'만 주고 "갑은 X로부터 3을 물려받았다"를 정답으로 낸 문항 → 확정 불가라 고침.)
4. **지문 해석이 갈리는 문장을 정답/오답의 기준으로 삼지 않는다.** 지문에 명시된 문장·직접 도출되는 관계만 근거로 쓴다.
5. 니체(인문08)·페로브스카이트(기술04)는 쓰지 않는다(사용자 요청).
6. 이전에 낸 문항(변형본, 고난도 가나다, 모의 1·2회, 미니, 1·2회 고난도판)과 겹치지 않게 새로 낸다.

### 5-3. 난이도 설계 — "정답 찾기"가 아니라 "오답 가려내기" 문제로
사용자가 "너무 쉽다"고 지적한 뒤 원인을 분석해 얻은 규칙이다. 처음 만든 문항은 정답이 가장 긴 선지인 비율이 71%(무작위 20%)였고, 오답이 처음부터 틀려서 지문을 안 읽고도 풀렸다.

**(1) 선지 길이·형식 균등**
- 5개 선지 길이 편차를 ±15% 안으로. 정답에만 붙던 "~므로/~하면서도" 근거를 오답에도 같은 분량으로 붙인다. 정답을 줄이거나 오답을 늘린다.
- `tools/lencheck.py`로 검사: 정답이 최장인 비율 약 20%(허용 15~30%), 최장·차장 쏠림도 확인(한때 정답이 대부분 두 번째로 길어지는 새 패턴이 생김 → 순위가 고르게 흩어지게 조정).
- 정답 번호는 ①~⑤에 고르게(5~8개씩). 같은 번호가 3번 연속 나오지 않게.

**(2) 오답은 "앞은 맞고 뒤만 틀린" 한 곳 변형** — 학교 기출 오답 방식
| 변형 방식 | 예 |
|---|---|
| 인과 뒤집기 | "항률 구간에서 배출 공기 온도가 낮은 것은 열에너지가 **소모되지 않기 때문**이다"(지문: 소모되기 때문) |
| 주체·대상 바꾸기 | ⓐ견해의 근거를 ⓑ견해에 붙임, 로크↔라이프니츠, (가)↔(나) |
| 원인·조건 하나 끼우기/빼기 | "부담이 이행되지 않으면 허가의 효력이 **곧바로 소멸**한다"(지문: 존속) |
| 범위·정도 과장 | "언제나/오직/전혀/마저/반드시/어떤 경우에도" |
| 개념 정의 맞바꾸기 | 과세 표준↔과세 물건, 정지 조건↔해제 조건, 증발기↔응축기 |
| 시점·기한 바꾸기 | 신고 기한 2년↔5년, 안 날부터 3개월↔보도 후 6개월, 성립↔확정 시점 |
| 지문 밖 내용 덧붙이기 | 정답 같은 문장 끝에 "이로써 본유론을 완전히 대체하려 했다" 식으로 지문에 없는 결론 추가 |
| 대응 오류 | <보기> 사례에 지문 개념을 잘못 짝지음(사례 A에 B의 유형 적용) |
- 한 선지에서는 **한 군데만** 바꾼다(두 군데 바꾸면 쉬워진다). 바꾼 위치는 선지마다 다르게(앞부분·뒷부분·조사 하나).
- 정답 선지도 지문 문장을 그대로 쓰지 않고 다른 표현으로 풀어 쓴다("역사가가 선택한 사실" → "역사가의 판단으로 사실의 위상이 달라지는 과정").

**(3) 선지 하나에 확인할 정보 2~3개, 서로 다른 단락에서**
- 예: "카는 ‘역사상의 사실’이 변화·재해석 가능성이 높아 역동적이라 보았고, 언어로의 전환 학자들은 사료를 저자의 기호 작업의 산물로 보아 과거의 실재와 동일시하지 않았다." — 앞 절은 (가) 둘째 단락, 뒤 절은 (나) 둘째 단락. 한쪽만 틀리게 비튼다.
- (가)(나)(다) 세트의 종합 문항은 반드시 세 지문의 정보를 한 선지 안에서 연결한다.

**(4) <보기> 사례 문항 — 규칙 3개 이상·행위자 3명 이상·값 2단계 이상**
- 법·행정 지문: 사람 A·B·C·D, 날짜 3개 이상, 서로 다른 유형이 섞인 사례(예: 표현대리 세 유형을 한 사례에 하나씩, 상속 개시일이 법 개정 전후로 갈리는 두 사람, 오늘 날짜를 주고 청구 가능 여부 판단).
- 과학·기술 지문: 표(3~5행) + 빈칸(A)(B)(C)를 먼저 구하고 비교 선지 판단(열펌프 COP 표, 연소 시험 3건, STR 4좌위 표, 분포 용적 3약물). 단위·관계식은 지문에 있는 것만.
- 인문·예술 지문: 지문에 없던 새 인물·작품·사건을 주고 지문의 인물 둘 이상이 어떻게 반응할지 묻는다("라투르라면~, 해러웨이라면~"). 정답은 "한 인물은 긍정, 다른 인물은 비판" 같은 비대칭 구조가 되게.
- <보기> 속 서술은 지문 용어를 직접 쓰지 말고 상황으로 풀어 쓴다("수달과 수생 곤충이 줄었다" → 지문의 '비인간 행위자'와 연결해야 풀림).

**(5) 워딩을 애매하고 어렵게(사용자: "훨씬 더 애매하게")**
- 지문 표현을 그대로 쓰지 않고 추상화한다: "사실의 위상", "신뢰가 형성된 상대방", "전제의 타당성을 무너뜨리는 방식", "증폭을 일으키는 상호 작용의 주체".
- 발문도 질문 형태를 바꾼다: "이유로 가장 적절한 것", "근거로 삼은 논리", "~를 반박할 때 취할 수 있는 입장", "공통된 문제의식", "서술 방식".
- 선지에 "그러나/다만/반면"으로 앞뒤를 대립시키고, 부정어("않는다/없다")를 중간에 숨긴다. 단, 문장이 비문이 되거나 지문 해석이 둘로 갈리게 하지는 않는다.

### 5-4. 유형별 출제 레시피
| 유형 | 만드는 법 | 점검 |
|---|---|---|
| 서술 방식·세트 관계 | 설명 대상/전개 순서/비교 기준을 선지마다 한 요소씩 바꿈 | 정답은 "A를 설명하고 B를 …" 처럼 지문 구조 2가지를 동시에 맞혀야 |
| 내용 일치(부정형) | 5선지 중 4개는 지문과 일치하되 모두 인과·근거절 포함, 1개만 한 군데 비틂 | 일치하는 4개가 지문 문장의 단순 복사가 아닌지 |
| ㉠㉡(㉮) 이유·비교 | 밑줄 앞뒤 문맥을 근거로 한 이유 선지 5개(원인 한 단계 건너뜀, 순서 뒤바뀜 등) | 정답 근거가 지문 어느 문장인지 말할 수 있어야 |
| <보기> 적용(사례) | 5-3 (4) | 정답을 직접 풀어 확인(§5-2 규칙 3) |
| ㄱㄴㄷㄹ 고르기 | 항목 4개 중 2~3개가 참. 각 항목에 근거절 포함, 참/거짓이 선지 조합에서 갈리게(ㄱㄴ, ㄱㄹ, ㄴㄷ, ㄱㄴㄹ, ㄴㄷㄹ 등 조합 5개 모두 그럴듯하게) | 한 항목만 알아도 2개 조합을 소거할 수 있는지(그러면 쉽다) |
| 문맥 어휘(ⓐ~ⓔ) | 바꿔 쓰기 선지(ⓐ: 동반한다고 …) 또는 같은 뜻 용례 고르기 | 지문에 ⓐ~ⓔ 표시가 있을 때만 |
| 표·수치 | 표 + 빈칸 → 값 계산 → 비교 선지 | 표 머리글 짧게(열 6개까지), 값이 정수로 떨어지게 |
| 관점 비교·비판 | "(나)의 관점에서 (가)를 비판", "A의 입장에서 B를 평가" — 두 관점의 차이를 선지에서 한 요소만 바꿈 | 비판이 지문 근거에서 도출되는지 |
| 단답형 | **사례 판별**: (a) 학생 5명 중 옳은 이름 모두, (b) ㉠㉡㉢ 사례를 지문 용어로 분류(확정 방식, 진리 유형, 지지체 유형, 약물 이동 단계), (c) 지문 용어 찾기는 음절·어절 조건으로 | 조건("2어절","3음절")을 어긴 답이 정답과 구별되게. 부분 점수 없음 명시 |

### 5-5. 세트 구성 규칙
- 세트당 선택형 2~5문항 + 필요 시 단답형 1: ①서술 방식/관계 → ②내용 일치 → ③㉠㉡ 비교·이유 → ④<보기> 적용(최고 배점) → ⑤ㄱㄴㄷㄹ 종합 → (⑥문맥 어휘).
- (가)(나)(다) 세트: 세트 관계 → (가)·(나)·(다) 각각의 인과 판단 → 종합 ㄱㄴㄷㄹ → 세 지문을 한 사례에 적용하는 <보기> → 단답형.
- 배점: 서술·내용 일치 2.6~3.0, 비교·이유 3.0~3.2, ㄱㄴㄷㄹ 3.2~3.5, <보기> 3.4~3.8, 문맥 어휘 2.4~2.6. 선택형 합 94점 + 단답 6점 = 100점(단답이 3점이면 선택형을 0.2씩 줄여 맞춤).
- 영역 순서: 인문 → 사회 → 기술/과학 → 예술 → … 기출처럼 섞되, 큰 복합 지문(과학 (가)(나)(다))은 뒤쪽에.

### 5-6. 출제 후 검증 체크리스트 (반드시)
1. 정답을 지문과 대조해 **직접 다시 푼다.** 특히 계산·날짜·표 문항은 값을 한 줄씩 계산해 정답 선지가 맞고, 나머지 4개가 틀렸는지 확인.
2. 오답 선지 4개 각각이 "지문의 어느 문장과 어긋나는가"를 한 줄로 말할 수 있어야 한다(말 못 하면 애매한 선지 → 수정).
3. `tools/qtool.py check`: 글꼴에 없는 글자(한자, Ⅰ~Ⅲ, ⓐ~ⓔ 등) 확인. `tools/lencheck.py`: 정답 최장 비율·번호 분포.
4. 발문의 "적절한/적절하지 않은" 방향과 정답 선지가 일치하는지, 정답이 정말 1개뿐인지.
5. 렌더 결과 확인: 표가 열 잘림 없이 들어갔는지, <보기> 줄바꿈, 단답형 답란, 쪽 끝에 발문만 남지 않았는지.
6. 정답표와 json의 `answer`가 일치하는지(`pos` 사용 시 자동 계산).

### 5-7. 자주 한 실수 (재발 방지)
- 정답이 가장 길다 / 정답에만 "~이므로" 근거가 있다 → 균등화.
- 오답이 상식적으로 틀려서 소거만으로 풀린다("사료 검증을 부정했다" 등) → 앞은 맞고 뒤만 틀리게.
- <보기>가 불완전해 정답이 확정되지 않는다 → 풀이 확인.
- 단답형이 지문 정의 문장 그대로의 빈칸 → 사례 판별형으로.
- 표 머리글이 길어 열이 잘린다 → 머리글 줄바꿈(렌더러에서 허용하도록 수정함)·열 수 제한.
- 같은 형식의 사례(친자 판별 표 등)를 여러 시험지에서 반복 → 유형을 바꿔 쓴다.
- 출제 후 사용자 답안(스캔)을 채점해 보면 쉬운 문항이 드러난다 → 정답률이 높았던 유형은 다음 회차에서 더 꼰다.
